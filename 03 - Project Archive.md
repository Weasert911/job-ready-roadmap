## Classification Rule

### Learning Projects

Use them to prove one competency. They need to run, demonstrate the target concept, and survive explanation and modification. Keep them organized in a monorepo or clearly named repositories; do not spend portfolio time polishing every exercise.

### Portfolio Projects

Promote only a few composition projects. A promoted project needs a clear README, architecture and engineering decisions, meaningful tests, CI, reproducible setup, screenshots or a demo when visual, deployment when applicable, and a history that is understandable to another engineer.

Promotion is earned by depth and usefulness, not project count.

## Archive Procedure

1. Add the repository or local path when work begins and set the row to `🟨`.
2. Build from memory after closing the resource.
3. Record the full evaluation in the current week of `02 - Weekly Tracker.md`.
4. Set the row to `✅` and check `01 - Skills.md` only after all four gates pass.
5. On failure, set `❌`, record the remediation, and reevaluate later. Preserve the failure as learning evidence.
